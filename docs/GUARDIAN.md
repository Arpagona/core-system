# Guardian déterministe — proposition pour revue

Guardian initial est un script sans LLM (`scripts/guardian.py`) : comparaison architecturale bornée et signaux de chemins sensibles. Il ne constitue **pas** un avis sémantique IA indépendant ni une revue indépendante de son auteur. Il ne détecte pas toutes les modifications d'API et n'exécute pas les tests Rust. La CI Rust est une vérification distincte obligatoire. Rapport JSON : `python3 scripts/guardian.py --base <commit> --ci unknown` ; SHA HEAD, base, signaux, anomalies, recommandations et limites. L'état CI est fourni par l'appelant et n'est pas vérifié par le script : `unknown` produit au minimum des réserves, `failure` produit à corriger. Ne jamais fournir `success` sans preuve externe portant sur le même SHA.

Le workflow exécute le code proposé avec un jeton de lecture uniquement, sans secret ni LLM ; une étape distincte publie un artefact privé. Ce n'est pas un audit indépendant de code hostile : une PR peut modifier le script et le workflow, et le code PR est exécuté dans le job. La revue de ces changements et la validation humaine sont indispensables. Les données de fichiers ne sont pas des instructions. Les signaux indiquent une revue élargie, pas une preuve que la modification est dangereuse ou conforme.

**ENFORCÉ** : contrôles exécutés par les jobs, permissions déclarées lecture seule. **PROCÉDURAL** : vérification de CI exacte, revue indépendante et accord des trois, avant intégration. **NON DISPONIBLE** : protection technique obligatoire de main sur la formule actuelle. Thibaud a autorisé le 10/11/2026 une réception procédurale des lots ; ce n'est pas une acceptation finale des trois ni une permission de fusion ou déploiement.
